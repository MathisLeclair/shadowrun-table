# i18n (English source, French dictionaries)

The app runs in French or English, **per user** (FR/EN switch). The code is written in English: every user-facing
string is an English key; French lives in flat JSON dictionaries. Nothing is translated by the server for the client:
the server sends English text **plus a key**, the browser translates. Tests: `node tools/test-i18n.ts` (ports
3800-3849), `node tools/test-i18n-sheet-map.ts` (port 3850).

Files: `client/lib/i18n.ts` (client API), `client/i18n/format.ts` (pure core: interpolation, plurals, lookup — shared by
client, server and tools), `client/i18n/fr/<area>.json` (French dictionaries), `client/i18n/legacy-fr-keys.json` (old
French keys → English keys), `server/lib/i18n.ts` (server `t()`/`tn()`, `errorBody()`, `normalizeLogEntry()`),
`tools/i18n-check.ts` (checker).

What goes through i18n: **everything that is not table story content.** Story content — campaign docs, quests,
handouts, NPC descriptions, seed/pack content, names typed by the GM, chat — stays as written.

## How it works

- `t('English text {name}', { name })` (`client/lib/i18n.ts`) returns the French entry of `client/i18n/fr/*.json`
  when the UI language is `'fr'`, else the English string — both with `{placeholders}` filled from the named params.
  **The key is the exact English string** (same apostrophes, spaces, punctuation).
- Missing French entry (or empty `""`) → the English text is shown and the key is recorded: `window.__i18nMissing` in
  the browser console, and Settings → « Translations » shows the count with a « Copy as JSON » button
  (`{ "key": "" }`, ready to paste into a dictionary).
- Dictionaries: `client/i18n/fr/<area>.json` = `{ "English text {n}": "Texte français {n}" }`. All files are loaded
  before the first render (`/i18n/fr/index.json` is generated by the server from the folder: a new file needs no code
  change). `glossary.json` is merged first; area files may override it.
- Language of a user: own choice (`game.me.lang`, stored in `state.users[id].lang`, GM: `config.gmLang`) › choice made
  in this browser before login (`localStorage['sr.lang']`, sent with the login) › table language (`game.config.lang`,
  default `fr`, GM sets it in Settings, admin in /admin). Action `users/setLang { lang: 'fr'|'en'|null }` (any user).
- Language switch: the root re-renders the whole tree and the page, dock and sheet are remounted (`key=lang`), so
  `useMemo`'d labels are recomputed. `useLang()` (ui-store.ts) exists for the rare component that must react itself.

### Context keys

The same English word sometimes needs two French translations (gender, plural, verb vs noun, abbreviation). The key
then carries a context before `::`, which the English display drops: `t('fem::hidden')` shows « hidden » in English and
« masquée » in French; `t('verb::Attack')` → « Attaquer »; `t('abbr::Soak')` → « Encaiss. ». Plural forms that are
identical in English get one too: `tn(n, '{n} online', 'pl::{n} online')`. Use a context only when the French really
differs.

### Saved data from before the switch

Until 2026-11 the source language was French, so saved data can still hold French keys: log entries
(`i18n.key`), history lines, token statuses (`'à terre'`), health states, metatype names (`'Humain'`), bestiary folders,
values imported from Chummer/Foundry. `client/i18n/legacy-fr-keys.json` maps each old French key to its English key;
`t()`, `tIfKnown()`, `logText()` (client) and `t()`, `formatSource()`, `errorBody()` (server) apply it, so old data keeps
translating in both languages. **Stored domain values stay as they are** (changing them would break existing saves and
comparisons in the code); display them with `t()`/`tIfKnown()`/`metatypeLabel()`. Do not delete entries from the legacy
map (old backups can be restored at any time).

## Client API

`import { t, tn, tk, … } from '../../lib/i18n.ts'`

| function | use |
|---|---|
| `t(key, params?)` | every user-facing literal. `params` = named values: `t('{actor} loses {n} boxes', { actor: a.name, n })` |
| `tn(n, one, other, params?)` / `tn(n, { zero?, one, other }, params?)` | plurals; `{n}` is always available. The form is chosen by the UI language's rule (French uses `one` for 0 and 1, English only for 1), then translated. Each form is its own key: `tn(k, '{n} mark', '{n} marks')` |
| `tk(key)` | marks a literal in a **constant table** for the checker, returns it unchanged; render with `t(value)`: `const STATUS = { draft: tk('Draft') }` … `{t(STATUS[s])}` |
| `tIfKnown(text, params?)` | text that MAY be a key (stored data, server text, old French keys): translated if known, else unchanged, never counted missing |
| `logText(entry)` | log entry text: `t(entry.i18n.key, entry.i18n.params)`, else `entry.text` (non-chat texts translated when known) |
| `errorText(reply)` | `{ error, errorKey?, params? }` → translated message (`send()`/`api()` already use it: `err.message` is translated, `err.key/params/code/status` kept) |
| `attrLabel('AGI')`, `attrShort('BOD')`, `skillLabel(skill or id)`, `skillGroupLabel(id)`, `skillCategoryLabel(cat)`, `limitLabel('social')`, `metatypeLabel(value)` | SR5 vocabulary — use instead of raw tables |
| `itemName(item)` | catalog item: English `name` / French `nameFr` by language — use instead of `item.nameFr \|\| item.name` |
| `fmtNumber(n)`, `fmtNuyen(n)`, `fmtDate(ts, opts?)`, `locale()`, `compare(a, b)` | locale-aware formatting/sorting |
| `getLang()` | current language ('fr'/'en') |

Item names stored in both languages on actors (`nameFr` / `nameEn`, `biName(item)` in log params):
[inventory.md](modules/inventory.md#names-in-both-languages).

## Rules for contributors

1. Write UI text in **English** and wrap **every** user-facing literal: text nodes, `title=`, `placeholder=`, `label=`,
   `hint=`, `aria-label=`, toasts, `confirmAction()`/`promptText()` messages, option labels, empty states, document
   titles: `<Button title={t('Delete')}>{t('Delete')}</Button>`.
2. Add the **French** to your area file: `client/i18n/fr/<area>.json` (areas: `map`, `sheet`, `combat`, `shop`,
   `training`, `audio`, `campaign`, `foundry`, `chummer`, `matrix`, `chargen`, `notes`, `books`, `assistant`, `city`…;
   `core`/`admin`/`glossary` belong to the core). Keep the placeholders identical. Use the official French SR5 terms of
   `glossary.json` (Chance, Constitution, Moniteur de condition, Repousser les limites…).
3. **Never concatenate translated fragments** and never put a variable in a key: `t('Give back {n} Essence points to
   {name}?', { n, name })`, not `'Give back ' + n + …` nor ``t(`Give back ${n}…`)``. Whole sentences only (word order
   differs in French). Prefer `tn()` over « point(s) ».
4. **Never call `t()` at module top level** (dictionaries are not loaded yet and the language changes at runtime):
   translate at render time; constant tables use `tk()` + `t(value)`.
5. Endonyms in a language picker (« Français », « English ») are never translated (`// i18n-ignore`).
6. Dates/numbers: `fmtDate`, `fmtNumber`, `fmtNuyen` instead of hard-coded locales.

## Server rules

- Errors: `ctx.fail('Text {x}', { x })` — key = English text with placeholders, params = named values
  (strings/numbers/booleans; a nested translatable value is `{ t: 'key', params }`). Static messages need no params:
  `ctx.fail('Character not found')`. The reply carries `error` (English text) and `errorKey`; the client translates.
- HTTP routes: `res.status(400).json(errorBody('Text {x}', { x }))` (`import { errorBody } from '../lib/i18n.ts'`);
  extra fields: `errorBody(key, params, { code })`.
- Log: `ctx.log({ kind, author, i18n: { key: '{actor} spends 1 Edge point', params: { actor: a.name } } })` —
  `text` is filled with the English rendering; LogDock shows `logText(entry)`. Roll labels / free text typed by users
  stay as typed.
- Shared modules (`shared/*.ts`): return English messages as plain strings when static (the client shows them with
  `t(msg)`, wrap them in `tk()` so the checker sees them), and `{ key, params }` objects for dynamic ones.
- Text that must be stored already translated (rare): `ctx.t(key, params)` renders in the table language
  (`server/lib/i18n.ts`: `t(lang, key, params)`, `tn(lang, n, …)` outside actions).
- Server console output, deploy scripts and tool output are developer-facing: plain English, no i18n.

## Checker

`node tools/i18n-check.ts [--area <area>] [files…] [--strict] [--json] [--unused]`

- Lists English keys used in code that have no French entry, keys built with `${…}` (must become params), dictionary
  problems (invalid JSON, placeholder mismatch), and **user-facing text not wrapped in `t()`** (JSX text nodes and
  `title=`/`placeholder=`/`aria-label=`/`label=` props, messages passed to `toast(`/`confirmAction(`/`promptText(`). A
  line containing `i18n-ignore` is skipped.
- `--area <area>` scans the area's client folder plus the server / shared files listed for it in `AREA_EXTRA` (top of
  `tools/i18n-check.ts`).
- Done = `node tools/i18n-check.ts --area <area> --strict` exits 0 and the module's tests pass. Then switch to FR in the
  app (top bar) and check the Settings counter while visiting your screens.
