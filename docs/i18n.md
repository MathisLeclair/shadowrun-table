# i18n (French source, English dictionaries)

The app runs in French or English, **per user**. French stays the source text in the code; English lives in flat JSON
dictionaries. Nothing is translated by the server for the client: the server sends French text **plus a key**, the
browser translates. Tests: `node tools/test-i18n.ts` (ports 3800-3849), `node tools/test-i18n-sheet-map.ts` (port
3850).

Files: `client/lib/i18n.ts` (client API), `client/i18n/format.ts` (pure core: interpolation, plurals — shared by client,
server and tools), `client/i18n/en/<area>.json` (dictionaries), `server/lib/i18n.ts` (server `t()`/`tn()`,
`errorBody()`, `normalizeLogEntry()`), `tools/i18n-check.ts` (checker).

## How it works

- `t('Texte français {name}', { name })` (`client/lib/i18n.ts`) returns the English entry of `client/i18n/en/*.json`
  when the UI language is `'en'`, else the French string — both with `{placeholders}` filled from the named params.
  **The key is the exact French string** (same apostrophes ’, spaces, punctuation).
- Missing English entry (or empty `""`) → the French text is shown and the key is recorded: `window.__i18nMissing` in
  the browser console, and Réglages → « Traductions » shows « Traductions manquantes : N » with a « Copier en JSON »
  button (`{ "clé": "" }`, ready to paste into a dictionary). Keys are recorded in both languages, so a French session
  also finds them.
- Dictionaries: `client/i18n/en/<area>.json` = `{ "Texte français {n}": "English text {n}" }`. All files are loaded
  before the first render (`/i18n/en/index.json` is generated by the server from the folder: a new file needs no code
  change). `glossary.json` is merged first; area files may override it. The same file must not translate one key two
  ways — use a context key (below).
- Language of a user: own choice (`game.me.lang`, stored in `state.users[id].lang`, GM: `config.gmLang`) › choice made
  in this browser before login (`localStorage['sr.lang']`, sent with the login) › table language (`game.config.lang`,
  GM sets it in Réglages, admin in /admin). FR/EN switch in the top bar, the login screen, the table picker and
  /admin; action `users/setLang { lang: 'fr'|'en'|null }` (any user).
- Language switch: the root re-renders the whole tree and the page, dock and sheet are remounted (`key=lang`), so
  `useMemo`'d labels are recomputed. `useLang()` (ui-store.ts) exists for the rare component that must react itself.

## Client API

`import { t, tn, tk, … } from '../../lib/i18n.ts'`

| function | use |
|---|---|
| `t(key, params?)` | every user-facing literal. `params` = named values: `t('{actor} perd {n} cases', { actor: a.name, n })` |
| `tn(n, one, other, params?)` / `tn(n, { zero?, one, other }, params?)` | plurals; `{n}` is always available. French uses `one` for 0 and 1, English only for 1. Each form is its own key: `tn(k, '{n} marque', '{n} marques')` |
| `tk(key)` | marks a literal in a **constant table** for the checker, returns it unchanged; render with `t(value)`: `const STATUS = { draft: tk('Brouillon') }` … `{t(STATUS[s])}` |
| `tIfKnown(text, params?)` | text that MAY be a key (stored data, server text): translated if the dictionary has it, else unchanged, never counted missing |
| `logText(entry)` | log entry text: `t(entry.i18n.key, entry.i18n.params)`, else `entry.text` (non-chat texts translated when known) |
| `errorText(reply)` | `{ error, errorKey?, params? }` → translated message (`send()`/`api()` already use it: `err.message` is translated, `err.key/params/code/status` kept) |
| `attrLabel('AGI')`, `attrShort('BOD')`, `skillLabel(skill or id)`, `skillGroupLabel(id)`, `skillCategoryLabel(cat)`, `limitLabel('social')`, `metatypeLabel('Nain')` | SR5 vocabulary (official English names for SKILLS ids) — use instead of `ATTR_LABELS[k]`, `SKILL_BY_ID[id].fr`, `SKILL_GROUPS[g]`… |
| `itemName(item)` | catalog item: English `name` / French `nameFr` by language — use instead of `item.nameFr \|\| item.name` |
| `fmtNumber(n)`, `fmtNuyen(n)`, `fmtDate(ts, opts?)`, `locale()`, `compare(a, b)` | locale-aware formatting/sorting (`nuyen()` of shared/util.ts is French-only) |
| `getLang()` | current language ('fr'/'en'), e.g. for `localeCompare(…, getLang())` |

Item names stored in both languages on actors (`nameFr` / `nameEn`, `biName(item)` in log params):
[inventory.md](modules/inventory.md#names-in-both-languages).

## Rules for translators (client)

1. Wrap **every** user-facing French literal: text nodes, `title=`, `placeholder=`, `label=`, `hint=`, `aria-label=`,
   toasts, `confirmAction()`/`promptText()` messages, option labels, empty states, document titles: `<Button
   title={t('Supprimer')}>{t('Supprimer')}</Button>`.
2. **Never concatenate translated fragments** and never put a variable in a key: `t('Rendre {n} point(s) d’Essence à
   {name} ?', { n, name })`, not `'Rendre ' + n + …` nor ``t(`Rendre ${n}…`)``. Whole sentences only (word order
   differs in English). Prefer `tn()` over « point(s) ».
3. **Never call `t()` at module top level** (dictionaries are not loaded yet and the language changes at runtime):
   translate at render time; constant tables use `tk()` + `t(value)`.
4. Add the English to **your area file only**: `client/i18n/en/<area>.json` (areas: `map`, `sheet`, `combat`, `shop`,
   `training`, `audio`, `campaign`, `foundry`, `chummer`, `matrix`, `chargen`, `notes`, `books`, `assistant`;
   `core`/`admin`/`glossary` belong to the core). Keep the placeholders identical (`{name}` stays `{name}`). Use the
   SR5 English terms of `glossary.json` (Edge, Body, Condition Monitor, Push the Limit, Overwatch Score, DV, AP…), and
   check the glossary before adding a term.
5. Ambiguous short words: a key may carry a context before `::` — `t('sort::Puissance')` shows « Puissance » in French
   and looks up `"sort::Puissance"` in the dictionary. Use it only when the same French word needs two English
   translations (the checker reports such conflicts).
6. Do **not** translate data: campaign story, quests, handouts, NPC descriptions, seeds, map/actor/item names typed by
   the GM, chat. Catalog items: `itemName(item)`. Skill/attribute labels: the helpers above. Stored French values
   (metatype 'Humain', status 'à terre'…): keep storing French, display with `t()`/`tIfKnown()`/`metatypeLabel()`.
7. Endonyms in a language picker (« Français », « English ») are never translated (add `// i18n-ignore` on the line if
   the checker flags them).
8. Dates/numbers: `fmtDate`, `fmtNumber`, `fmtNuyen` instead of hard-coded `'fr-FR'`.

## Server rules

- Errors: `ctx.fail('Texte {x}', { x })` — key = French text with placeholders, params = named values
  (strings/numbers/booleans; a nested translatable value is `{ t: 'clé', params }`). Static messages need no params:
  `ctx.fail('Personnage introuvable')` is already translatable (the key is the message). A template literal in
  `ctx.fail(\`… ${a.name} …\`)` works but is untranslatable → convert to params. The English goes in the area
  dictionary (the client translates `errorKey`).
- HTTP routes: `res.status(400).json(errorBody('Texte {x}', { x }))` (`import { errorBody } from '../lib/i18n.ts'`);
  extra fields: `errorBody(key, params, { code })`.
- Log: `ctx.log({ kind, author, i18n: { key: '{actor} dépense 1 point de Chance', params: { actor: a.name } } })` —
  `text` is filled with the French rendering; LogDock shows `logText(entry)`. Roll labels / free text typed by users
  stay as typed.
- Shared modules (`shared/*.ts`, used by both sides): return French messages as plain strings when static (the client
  shows them with `t(msg)` — define a local `const tk = (s) => s` and wrap them so the checker sees them), and `{ key,
  params }` objects for dynamic ones (client: `t(m.key, m.params)`, server: `ctx.fail(m.key, m.params)`).
- Text that must be stored already translated (rare, e.g. a generated document): `ctx.t(key, params)` renders in the
  table language (`server/lib/i18n.ts` reads the same dictionaries; `t(lang, key, params)`, `tn(lang, n, …)` outside
  actions).
- Transient events carrying text to show (`emitTo(…, { note })`): send keys + params too and translate client-side.

## Checker

`node tools/i18n-check.ts [--area <area>] [files…] [--add-missing=<area>] [--strict] [--json] [--unused]
[--no-literals]`
- Lists `t()/tn()/tk()` keys and server `ctx.fail()/errorBody()/i18n.key` keys that have no English entry, keys built
  with `${…}` (must become params), dictionary problems (invalid JSON, non-string values, placeholder mismatch, one key
  translated two ways), and **suspicious untranslated French literals** (heuristic: accented letters / common French
  words in JSX text nodes, `title= placeholder= label= hint= alt= aria-label=`, and literals passed to `toast(
  confirmAction( promptText( setErr( Error(` or `label:/title:/hint:/placeholder:` props). A line containing
  `i18n-ignore` is skipped.
- `--area <area>` scans the area's client folder `client/modules/<area>/` plus the server / shared files listed for it
  in `AREA_EXTRA` (top of `tools/i18n-check.ts`); other files can be passed explicitly (e.g. `node tools/i18n-check.ts
  server/modules/75-notes.ts --strict`).
- `--add-missing=sheet` appends the missing keys of the scanned files to `client/i18n/en/sheet.json` with `""` values
  (empty = still missing), ready to translate.
- Done = `node tools/i18n-check.ts --area <area> --strict` exits 0, with no dynamic key and no literal left in your
  files (or only justified `i18n-ignore`), and the module's tests still pass (`test-client.ts` `send()` still rejects
  with the French `error` text, so existing assertions keep working). Then switch to EN in the app (top bar) and check
  the Réglages counter while visiting your screens.
