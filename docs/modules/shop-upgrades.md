# Shop: upgrades, lifestyles, martial arts

Buying things that are installed on something the character already owns. Schema of the nested lists:
[characters.md](characters.md#nested-items-accessories-mods-options-techniques). Server `server/modules/40-shop.ts`,
rules `client/modules/shop/rules.ts`, client preview `client/modules/shop/upgrades.ts` (`upgradePreview`; the server
stays the authority). Tests: `node tools/test-shop.ts` (port 3250), `node tools/test-lifestyle.ts` (ports 3251-3252).

Shop-installed sub-items also carry `paid` (price paid; resale value = `paid`, else `cost`; included parts are worth 0
and never sold alone), accessories `extraMount` (mount points they add, e.g. slide mount), armor mods `bonus` (`{
fire|cold|electricity|acid|falling|toxin|pathogen|radiation: n }` evaluated at the rating), vehicle mods `effects` (`{
handling, speed, accel, armor, body, sensor, pilot, seats }` evaluated at the rating; never applied to the stored
vehicle stats).

## Catalogs

`tools/build-catalog.ts`; id = Chummer GUID, `nameFr` from `lang/fr-fr_data.xml`, same price/avail fields as the other
catalogs. Formulas may use the TARGET's values (`rules.ts quote(item, { vars })`, `evalFormula` accepts extra
variables, `div`, `mod`): `WeaponCost`, `ArmorCost` + `Capacity`, `VehicleCost` + `Body Speed Handling Acceleration
Pilot Sensor Seats Armor`; `stats.targetCost: true` flags them.
- `accessories` (weapons.xml `<accessories>`): `stats { mount: ['Top','Under'] ([] = no mount needed), extraMount?,
  accuracy?, rc?, rcGroup?, conceal?, smartgun? (no Accuracy: +1 die wired / +2 wireless, a note), requires?/forbids?: {
  names?, namesContains?, categories?, categoriesContains?, types? } }` (any listed value matches; `*Contains` = Chummer
  `operation="contains"`, e.g. Shock Pad « Rifles », drone mods « Drones »; only name / category / type are read: a
  required OR group that also tests conceal / ammo / useskill / NOT… is dropped — it passes — and unknown forbidden
  conditions never forbid). Weapons gain `stats.mounts` (`<accessorymounts>`) and `stats.included: [{ id?, name }]`
  (accessories delivered with the weapon).
- `armormods` (armor.xml `<mods>`, « Custom Liners » kept as « Armor Liners (Rating N) »): `stats { capacity: n |
  formula (Rating, Capacity), armor?, bonus? }`. Armors keep `stats.capacity`.
- `vehiclemods` (vehicles.xml `<mods>`): `stats { slots: n | formula, ratingVar?: 'Body'|'Seats'|'qty' (max rating from
  the vehicle), bonus?, requires?/forbids? (same shape as accessories) }`. Vehicles gain `stats.modSlots` (drones: extra
  slots, one pool = Body + modSlots) and `stats.slotBonus { Powertrain|Protection|Weapons|Body|Electromagnetic|Cosmetic:
  n }` (`<xxxmodslots>`: other vehicles have one pool per category = Body + slotBonus[category], R5).
- `lifestylequalities` (lifestyles.xml `<qualities>`: SR5 + Run Faster Garage, Workshop, DocWagon, Extra Secure…):
  `cost` (¥/month, may be < 0), `stats { multiplier? (%; baseOnly: Chummer <multiplierbaseonly>, % of the base only),
  lp, allowed?: [base lifestyles], multiple?, selectText?, comforts?, security?, neighborhood?, forbids?: [option names]
  / requiresOneOf?: [option names] (<forbidden>/<required> <oneof><lifestylequality>), requiresLifestyle?: [bases] }`.
  `lifestyles` gain `stats { lp, points: { comforts|neighborhood|security: [min, max] }, pointCost? }`.
- `martialarts` (martialarts.xml, karma): `stats { karma, techniqueKarma: 5, techniques: [{ id, name, nameFr?, source,
  page }] }` (not in SHOP_FILES).
- `data/catalog/coverage.md` = items per source book, Chummer XML vs catalog, with the dropped entries and why
  (regenerated by the build).
- Every entry has `source` + `page` (📖 chips). Model-specific vehicle mods have no page in Chummer (« ? »: Enviroseal,
  Smart Tires…): the build gives them the page of the vehicle that ships them. Only 3 Chummer entries keep no page
  (Essence Hole / Antihole, HK MP75: « 0 » in Chummer).

## Rules (`client/modules/shop/rules.ts`)

`UPGRADE_FILES` (file → `{ list, sub }`), `STORE_SECTIONS` (= `SECTIONS` + `UPGRADE_SECTIONS` « Accessoires d’armes »,
« Modifications d’armure », « Modifications de véhicule », « Arts martiaux »; `SECTIONS`, used by the character
creator, gains only the lifestyle options in « Train de vie »), `weaponMounts / freeMounts / accessoryFit / accessoryMoves / weaponSlots` (mount
points of the weapon — own `mounts`, else the catalog's (none when the catalog entry has no `<accessorymounts>`: bows,
holdouts…), else standard ones for ranged weapons without catalog entry — minus mounts taken by non-included
accessories; requires/forbids; no duplicate), `upgradeAvail(q, item, targetQuote)` (relative availability,
[rules](../rules/availability-and-shop.md#legality-and-limits)), `armorCapacity / armorModFit` (capacity =
`armor.capacity` › catalog › rating; Σ mod capacity ≤ capacity), `vehicleVars / vehicleSlotPool / vehicleSlots(vehicle,
cat, pool) / vehicleSlotsUsed(vehicle, pool) / vehicleModFit` (`vehicle.slots` overrides; drones and vehicles without
catalog entry: one pool 'all' = Body + modSlots; other vehicles: the mod's category pool `VEHICLE_SLOT_CATEGORIES` =
Body + slotBonus[category]; « All », « Model-Specific » and drone-attribute categories take no pool → not limited),
`vehicleModEffects`, `upgradeFields(file, entry, parent, { rating, parentCat, parentValue })` (sheet editor),
`lowersRent(q)`, `MARTIAL_KARMA`, `martialKarma(style, known, n)`. Lifestyle helpers: [lifestyles.md](lifestyles.md#state).

## Actions

- `shop/buy` / `shop/give` lines accept `target: { itemId }` (weapon / armor / vehicle / lifestyle id) for upgrade
  catalogs and `mount` (accessories); the lines of one order are checked together (two Barrel accessories refused).
  Prices: catalog formulas with the target's values. Lifestyle option prices and the rent rule:
  [lifestyles.md](lifestyles.md#buying-and-paying). Options that lower the rent (`lowersRent`: category 'Negative',
  negative cost or multiplier) bought by a player ALWAYS wait for the GM (whatever the approval mode; order flag
  `rent`, line `lowersRent`); the storefront shows « Validation MJ ». Upgrade lines are re-checked when a pending order
  is approved. GM gifts skip prices and legality, never the fit (mounts, capacity, slots).
- Bought weapons get `mounts` and their included accessories (`included: true`, mount 'Internal'); bought armors get
  `capacity`.
- `shop/sell { …, subId }` sells an installed accessory / mod (sell rate × `paid`/`cost`); selling a weapon / armor /
  vehicle sells its installed parts with it.
- `shop/removeUpgrade { actorId, list: 'weapons'|'armor'|'vehicles'|'lifestyles', itemId, subId }` removes without
  refund (players: own actor, not rent-lowering lifestyle options — category 'Negative' / negative cost or multiplier —
  nor built-in parts: GM only).
- Martial arts: the storefront section (`MartialArts.tsx`) sends a `martialArt` training request (`training/request`,
  [training.md](training.md#actions-and-behaviour)): GM approval per the training settings, training time, instructor
  option, downtime days (RG p.128, [rules](../rules/advancement.md#martial-arts-rg-p-128)). It shows the quote (karma,
  instruction nuyen, time) and the style's pending / in-progress training.
- `shop/martialArt { actorId, styleId, techniqueIds, free? }` (GM only): granted at once, no training time — karma per
  `martialKarma` ([rules](../rules/availability-and-shop.md#martial-arts-rg-p-128)), `free` = no karma (the storefront's
  « Grant for free »). Pending orders `kind: 'karma'` from older saves (players used to ask here) are still approved by
  `shop/resolve`.
- `shop/setAccessory { actorId, weaponId, subId, equipped?, mount? }` (owner or GM): switches an installed accessory on /
  off (`equipped: false` stored, `true` clears the flag; built-in parts too) and / or moves it to another mount point
  (`accessoryMoveProblem`: one of the mounts its catalog entry accepts — standard ones for a hand-made accessory —, that
  the weapon has and no other accessory uses; built-in parts, `''` and « Internal » accessories never move). A
  switched-off accessory keeps its mount. Logged (« {actor} moves {item} to the {mount} mount of {target} », « switches
  on / off »); returns `{ mount, equipped }`.

## Weapon slots (players)

`rules.ts weaponSlots(weapon, weaponCat)` → one row per standard mount + « Internal »: `state` 'used' / 'free' / 'none'
(the weapon lacks it) and the accessories on it (Internal: built-in parts and internal accessories, never limited);
`accessoryMoves(weapon, weaponCat, acc, accCat)` = where an accessory can move. `shop/WeaponSlots.tsx` draws that board
with the on / off switch and the move select (owner / GM), used by:
- the shop tab « Customize weapons » (`Customize.tsx`): pick a weapon, pick a free slot, the catalog accessories that
  fit that mount (`accessoryFit` with that mount) are listed with price / availability; one opens the usual
  `ItemDetail` with the target weapon and mount preset (`targetId` / `mount` props): cart, availability test, GM sell /
  give. Cart lines already aimed at a mount of the weapon show « in the cart » on that slot.
- the sheet (Combat tab): the « ⚙ » button after a weapon's accessory chips (`sheet/accessories-ui.tsx`). The chips
  show the mount of each accessory (`SubChips`).
